# TeleHack

Мод-твик для **Telegram iOS** (в духе iUgram / AyuGram): набор плагинов, которые включаются
прямо внутри приложения. Работает как dylib — встраивается в расшифрованный IPA (без джейлбрейка,
через TrollStore / Sideloadly / AltStore / LiveContainer) или ставится .deb-пакетом на джейлбрейке.

## Плагины

| Раздел | Плагин | Что делает |
|---|---|---|
| Призрак | Скрыть «в сети» | Не отправляет `account.updateStatus` — вы не появляетесь онлайн, «был(а) недавно» замирает |
| Призрак | Не читать сообщения | Блокирует `readHistory` (ЛС, группы, каналы, секретные чаты), упоминания, реакции, комментарии |
| Призрак | Не отмечать прослушанным | Голосовые и кружки остаются «непрослушанными» |
| Призрак | Скрыть «печатает…» | И «записывает голосовое», «выбирает стикер» и т.п. |
| Призрак | Анонимные истории | Вы не попадаете в список просмотревших |
| Призрак | Прочитать сейчас | Кнопка: на 30 секунд пропускает отметки о прочтении |
| Приватность | Не накручивать просмотры | Каналы не засчитывают ваш просмотр |
| Реклама | Убрать рекламу | Блокирует загрузку спонсорских сообщений в каналах |
| Свои правила | Блокировка по ID | Любой MTProto-метод по constructor ID (hex) |
| Отладка | Журнал запросов | Последние 300 исходящих запросов — помогает найти ID после обновлений Telegram |

**Открыть панель:** зажать экран **тремя пальцами** (~0.6 с). При первом запуске появится подсказка.

## Как это работает

Telegram iOS почти целиком на Swift, но сетевой слой (MtProtoKit) — Objective-C. Каждый
API-вызов проходит через `-[MTRequestMessageService addRequest:]`. TeleHack перехватывает этот
метод, читает первые 4 байта сериализованного запроса (TL constructor ID) и, если для него
включён плагин, просто не отправляет запрос на сервер.

Хуки сделаны через Logos с генератором `internal` (обычный ObjC runtime swizzling), поэтому
dylib **не зависит от CydiaSubstrate/ElleKit** и его можно вшить в IPA.

```
Sources/
  Tweak.x          — хук MTRequestMessageService, точка входа
  THNetFilter.m    — разбор constructor ID и решение «пропустить/заблокировать»
  THFeatures.m     — реестр плагинов и их constructor ID
  THSettings.m     — настройки (NSUserDefaults, префикс telehack.)
  THLog.m          — журнал запросов
  THPanel.m        — UI: панель настроек и журнал
```

### Добавить свой плагин

Добавьте запись в `+[THFeatures all]` (`Sources/THFeatures.m`): ключ, раздел, название,
описание и список constructor ID. Всё остальное (переключатель в панели, фильтрация) подхватится
автоматически.

## Сборка

Собирается в GitHub Actions (`.github/workflows/build.yml`) на Ubuntu-раннере (Linux-тулчейн Theos) при каждом пуше.
В артефакте `TeleHack-tweak`: `TeleHack.dylib` и .deb (rootless и rootful).

**Готовый IPA:** Actions → *Build TeleHack* → *Run workflow* → вставить прямую ссылку на
**расшифрованный** Telegram IPA. В артефакте `Telegram-TeleHack-ipa` будет пропатченный IPA
(через [cyan](https://github.com/asdfzxcvbn/pyzule-rw)). Не коммитьте IPA в репозиторий и
не делайте репозиторий публичным с такими артефактами — это чужое приложение.

Локально (macOS + [Theos](https://theos.dev)):

```sh
make package FINALPACKAGE=1 THEOS_PACKAGE_SCHEME=rootless   # .deb
cyan -i Telegram.ipa -o Telegram-TeleHack.ipa -f .theos/obj/TeleHack.dylib   # IPA
```

## Ограничения и нюансы

- Заблокированный запрос не отправляется вообще. Если вы прочитали чат в режиме призрака и потом
  выключили его, отметка о прочтении может уйти только после перезапуска Telegram (или когда вы
  прочитаете в чате новое сообщение).
- Отправка сообщения сервер всё равно засчитывает как активность — вы на короткое время станете «в сети».
- Если в новой версии Telegram сменится слой API и какой-то метод получит новый constructor ID,
  включите журнал, найдите новый ID и добавьте его в «Свои правила» (или в `THFeatures.m`).

## Планы

- Сохранение удалённых сообщений и истории редактирования (anti-revoke) — нужен разбор входящих апдейтов.
- Подмена модели устройства в `initConnection`.
- Пункт TeleHack прямо в настройках Telegram.
